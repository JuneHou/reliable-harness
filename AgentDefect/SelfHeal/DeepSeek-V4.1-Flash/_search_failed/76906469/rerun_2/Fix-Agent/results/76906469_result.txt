Why the original code did not remember anything:
`AgentType.CHAT_ZERO_SHOT_REACT_DESCRIPTION` builds its prompt with
`ChatAgent.from_llm_and_tools()`, whose default chat prompt is

    [SystemMessage(tools + json format instructions),
     HumanMessage("{input}\n\n{agent_scratchpad}\n\n(reminder...)")]

That prompt has NO `chat_history` placeholder, so its `input_variables` are
only `["input", "agent_scratchpad"]`. `Agent.get_full_inputs()` only injects the
memory value when the prompt actually declares a `chat_history` variable:

    if "chat_history" in self.llm_chain.prompt.input_variables:
        new_inputs["chat_history"] = kwargs["chat_history"]

Because the default prompt lacks it, the `ConversationBufferMemory` attached to
the agent was silently loaded and then thrown away - no error, just an agent
that behaves like it has amnesia ("what is the last question I asked?" can't be

Fix (a "prompt" fix):
1. Build an explicit ChatPromptTemplate that keeps the ReAct chat-agent system
   instructions but adds `MessagesPlaceholder(variable_name="chat_history")`
   between the system message and the human message.
2. Use `ConversationBufferMemory(memory_key="chat_history", return_messages=True)`
   so the memory returns chat messages (not a raw string) that fit the
   MessagesPlaceholder - the memory key must equal the placeholder name.
3. Pass that prompt through `agent_kwargs={"prompt": prompt}` (and keep
   `memory=memory` on `initialize_agent`).
"""

from langchain_openai import ChatOpenAI
from langchain.agents import initialize_agent, AgentType
from langchain.agents import load_tools
from langchain.memory import ConversationBufferMemory
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from dotenv import load_dotenv
import os

load_dotenv()
api_key = os.getenv("OPENAI_API_KEY")
if not api_key:
    raise ValueError("OPENAI_API_KEY is not set in environment or .env file")

llm = ChatOpenAI(
    model_name="gpt-4",
    temperature=0,
    openai_api_key=api_key
)

tools = load_tools(["llm-math", "wikipedia"], llm=llm)

# ---------------------------------------------------------------------------
# Prompt with an explicit place for the conversation history
# ---------------------------------------------------------------------------
SYSTEM_TEMPLATE = """Respond to the human as helpfully and accurately as possible. You have access to the following tools:

{tools}

Use a json blob to specify a tool by providing an action key (tool name) and an action_input key (tool input).

Valid "action" values: "Final Answer" or {tool_names}

Provide only ONE action per $JSON_BLOB, as shown:

{{
  "action": $TOOL_NAME,
  "action_input": $INPUT
}}

Follow this format:

Question: input question to answer
Thought: consider previous and subsequent steps
Action:
```
$JSON_BLOB
```
Observation: action result
... (repeat Thought/Action/Observation N times)
Thought: I know what to respond
Action:
```
{{
  "action": "Final Answer",
  "action_input": "Final response to human"
}}
```

The previous conversation with the human is provided above under the human/ai
messages: use it to resolve references (pronouns, "the last question", etc.) and
to answer questions about the conversation itself without calling a tool.

Begin! Reminder to ALWAYS respond with a valid json blob of a single action. Use tools if necessary. Respond directly if appropriate. Format is Action:```$JSON_BLOB```then Observation"""

HUMAN_TEMPLATE = """{input}

{agent_scratchpad}

(reminder to respond in a JSON blob no matter what)"""

tool_descriptions = "\n".join(
    f"{tool.name}: {tool.description}" for tool in tools
)
tool_names = ", ".join(tool.name for tool in tools)

prompt = ChatPromptTemplate.from_messages(
    [
        ("system", SYSTEM_TEMPLATE),
        # <-- the missing piece: gives the agent a slot for chat history
        MessagesPlaceholder(variable_name="chat_history"),
        ("human", HUMAN_TEMPLATE),
    ]
).partial(tools=tool_descriptions, tool_names=tool_names)

# memory_key MUST match the MessagesPlaceholder name; return_messages=True
# makes the memory produce real messages instead of a single formatted string.
memory = ConversationBufferMemory(
    memory_key="chat_history",
    return_messages=True,
    output_key="output",
)

agent_test = initialize_agent(
    tools=tools,
    llm=llm,
    agent=AgentType.CHAT_ZERO_SHOT_REACT_DESCRIPTION,
    handle_parsing_errors=True,
    memory=memory,
    verbose=False,
    agent_kwargs={"prompt": prompt},
)


def run_agent(prompt_text: str) -> str:
    return agent_test.run(prompt_text)


if __name__ == "__main__":
    result1 = run_agent("what is the capital of France?")
    print(result1)

    result2 = run_agent("what is the last question I asked?")
    print(result2)

    # Sanity check: the memory really holds both turns now.
    print(memory.load_memory_variables({})["chat_history"])

### 2. Structural validation
`validate_fixed_code` returned **ACCEPT** — imports resolve, `run_agent` exists and returns a `str`, and the module layout matches the test's expectations. So the *shape* is fine.

### 3. API verification (the decisive part)

The bug diagnosis is **correct**. `Agent.get_full_inputs()` only injects `chat_history` when the LLM chain's prompt declares it:

```
if "chat_history" in self.llm_chain.prompt.input_variables:
    new_inputs["chat_history"] = kwargs["chat_history"]
```

And `ChatAgent.create_prompt()` (confirmed from reference docs) builds only:

```
system_message_prefix / system_message_suffix + human_message="{input}\n\n{agent_scratchpad}"
→ input_variables = ["input", "agent_scratchpad"]
```

i.e. **no `chat_history` slot**. So the original `ConversationBufferMemory` really was dead weight.

**But the fix does not work**, because of how the prompt is injected. Verification of `ChatAgent.from_llm_and_tools` shows its real signature is:

```
from_llm_and_tools(llm, tools, callback_manager=None, output_parser=None,
                   system_message_prefix=..., system_message_suffix=...,
                   human_message=..., format_instructions=..., input_variables=None, **kwargs)
```

There is **no `prompt` parameter**, and there is **no `if "prompt" in kwargs` escape hatch** (unlike `ConversationalChatAgent`, which exposes `memory_prompts`). The internal implementation unconditionally does:

```
prompt = cls.create_prompt(tools, system_message_prefix=..., human_message=..., ...)
llm_chain = LLMChain(llm=llm, prompt=prompt)
return cls(llm_chain=llm_chain, allowed_tools=tool_names, output_parser=..., **kwargs)
```

So `agent_kwargs={"prompt": prompt}` flows into `**kwargs` → `ChatAgent(llm_chain=..., prompt=<template>)`. `ChatAgent` is a Pydantic `BaseModel` whose only fields are `llm_chain`, `output_parser`, `allowed_tools`, `return_stopped_response`, `early_stopping_method`, etc. — `prompt` is not a field, and the default `Extra.ignore` config means the kwarg is **silently discarded** (at best; in stricter configs it raises). Either way the custom template never reaches the LLM chain, so the agent keeps using `create_prompt()`'s history-less prompt.

Net effect: `input_variables` is still `["input", "agent_scratchpad"]`, `chat_history` is never forwarded, and the memory is just as inert as before.

### 4. Why the test will fail
`run_agent("what is the capital of France?")` then `run_agent("what is the last question I asked?")` — the model receives no prior turns, so it will answer that it has no access to previous questions. `self.assertIn("france", response.lower())` fails.

Complicating matters, the added sanity check masks this:

```
print(memory.load_memory_variables({})["chat_history"])
```

`AgentExecutor` calls `memory.save_context()` unconditionally, so the buffer **does** fill up regardless of whether the prompt consumes it. The print will happily show both turns, giving a false "memory works" signal while the LLM never sees them.

### 5. What a working fix looks like
- Convert to `AgentType.CHAT_CONVERSATIONAL_REACT_DESCRIPTION` (its native prompt already declares `chat_history`), or
- Build the agent through a supported path that accepts a prompt (e.g. a custom prompt-bearing agent constructor / `create_structured_chat_agent`-style factory), rather than smuggling `prompt` through `agent_kwargs`.

Also note `ConversationBufferMemory` + `MessagesPlaceholder` requires `return_messages=True` with matching `memory_key` — that part of the fix was reasoned correctly, which makes the silent-drop of the prompt the sole (but fatal) flaw.
