    """Decorate a function with package and import requirements

    Args:

        global_imports (List[Import], optional): Required imports. Defaults to [].

Since `@dataclass` defaults to `eq=True, frozen=False`, it sets `__hash__ = None`, making these instances **unhashable**. Putting them in a set raises `TypeError: unhashable type: 'Alias'` — exactly what the reproduce script detects. The test's `template_function1` (with `Alias("pandas", "pd")`) triggers the bug, and `template_function2` (with `ImportFromModule`) would too.

## Fix Evaluation

**1. The `__hash__` approach is correct.** In CPython's `dataclasses.py`, the decorator computes:
```python
class_hash = cls.__dict__.get('__hash__', MISSING)
has_explicit_hash = not (class_hash is MISSING or (class_hash is None and '__eq__' in cls.__dict__))
```
When a class explicitly defines `__hash__` in its body (as the fix does), `has_explicit_hash` is True and the dataclass does **not** overwrite it with `None`. So `@dataclass` still generates field-based `__eq__`/`__init__`, while the explicit `__hash__` survives. This is the canonical idiom for making dataclasses hashable.

**2. Hash/eq consistency holds.** `Alias.__eq__` compares `(name, alias)` and `__hash__` returns `hash((name, alias))` — matched. `ImportFromModule.__eq__` compares `(module, imports)` and `__hash__` returns `hash((module, *imports))` — if two instances are equal (same module, same list contents), their flattened tuples are equal, so hashes match. The `a == b ⟹ hash(a) == hash(b)` invariant is satisfied, and set-based deduplication now works correctly.

**3. Both module copies patched.** The fix applies identical `__hash__` methods in both `autogen_core/code_executor/_func_with_reqs.py` (clean path) and the deprecated `components/code_executor/` copy — consistent with the codebase's dual-module structure. The deprecated path's `@deprecated` wrapper doesn't break hashing whether it patches `__new__` in place or returns a subclass (a subclass inherits `__hash__`).

**4. Reproduce script passes.** The test imports from `autogen_core.code_executor` (the clean path, no `@deprecated`): constructing `FunctionWithRequirements` doesn't hash anything; `build_python_functions_file` now successfully sets `Alias`/`ImportFromModule` into the set, `_import_to_str` emits `import pandas as pd` / `from pandas import DataFrame, concat`, no exception → exit code 0 for "fixed". The buggy version raises "unhashable type" → exit 0 for "buggy". Both branches behave consistently.

**5. New tests are sound.** The added tests exercise the full executor path with `Alias` and `ImportFromModule` imports, which forces the set-collection code that previously crashed. Arithmetic checks out: `floor(1+2+π)=6` ✓, `m.floor(4+5)=9` ✓, `floor(3+4+π)=10` ✓ (3+4=7, +3.14159 = 10.14). `_import_to_str(ImportFromModule("math", ["floor", Alias("pi","PI")]))` correctly yields `from math import floor, pi as PI`. Keyword construction (`Alias(name=..., alias=...)`, `ImportFromModule(module=..., imports=[...])`) matches the dataclass field names. The required re-exports from `autogen_core.code_executor` already exist in the buggy code (the reproduce script depends on them), and the diff doesn't modify any `__init__.py`.

**6. Structural validation passed** — every file present once with full text. The diff's other changes (blank-line removals between file sections) are purely cosmetic.

The `verify_api_usage` searches returned only generic documentation, but the relevant semantics — explicit `__hash__` preservation under `@dataclass` — is well-established CPython behavior, and this fix matches the canonical upstream autogen fix for this exact issue.

## Verdict

**ACCEPT**

The fix correctly identifies and resolves the root cause (dataclass-generated unhashability colliding with set-based import collection), uses the standard idiom (explicit `__hash__` consistent with generated `__eq__`), applies it to both module copies, adds meaningful regression tests with correct expected outputs, and makes the reproduce script's "fixed" path succeed without introducing regressions to the existing tests.

def with_requirements(
    python_packages: Sequence[str] = [], global_imports: Sequence[Import] = []
) -> Callable[[Callable[P, T]], FunctionWithRequirements[T, P]]:
    """Decorate a function with package and import requirements

    Args:
        python_packages (List[str], optional): Packages required to function. Can include version info.. Defaults to [].
        global_imports (List[Import], optional): Required imports. Defaults to [].

    Returns:
        Callable[[Callable[P, T]], FunctionWithRequirements[T, P]]: The decorated function
    """

    def wrapper(func: Callable[P, T]) -> FunctionWithRequirements[T, P]:
        func_with_reqs = FunctionWithRequirements(
            python_packages=python_packages, global_imports=global_imports, func=func
        )

        functools.update_wrapper(func_with_reqs, func)
        return func_with_reqs

    return wrapper


def build_python_functions_file(
    funcs: Sequence[Union[FunctionWithRequirements[Any, P], Callable[..., Any], FunctionWithRequirementsStr]],
) -> str:
    """:meta private:"""
    # First collect all global imports
    global_imports: Set[Import] = set()
    for func in funcs:
        if isinstance(func, (FunctionWithRequirements, FunctionWithRequirementsStr)):
            global_imports.update(func.global_imports)

    content = "\n".join(map(_import_to_str, global_imports)) + "\n\n"

    for func in funcs:
        content += _to_code(func) + "\n\n"

    return content

        docstring = '"""' + docstring + '"""'
        docstring = indent(docstring, "    ")
        content += docstring + "\n"

    content += "    ..."
    return content
