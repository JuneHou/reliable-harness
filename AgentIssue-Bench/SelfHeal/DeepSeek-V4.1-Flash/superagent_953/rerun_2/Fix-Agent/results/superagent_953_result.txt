Verdict: ## Evaluation of `superagent_953`

### Root cause of the bug
The reported error was `supabase: not found`. The runner image started with:
```sh
command: /bin/sh -c "npm run supabase:docker:push --debug && npm start"
```
which shells out to the `supabase` CLI binary. That binary was neither a `package.json` dependency nor present in the `node:18-buster` runner image, so the container failed immediately at startup.

### What the fix does
1. **`libs/ui/Dockerfile` (runner stage)** — installs the Supabase CLI:
   ```dockerfile
   RUN set -eux; \
       ARCH="$(dpkg --print-architecture)"; \
       SUPABASE_VERSION="1.115.0"; \
       curl -fsSL -o /tmp/supabase.deb \
           "https://github.com/supabase/cli/releases/download/v${SUPABASE_VERSION}/supabase_${SUPABASE_VERSION}_linux_${ARCH}.deb"; \
       dpkg -i /tmp/supabase.deb || apt-get install -y -f; \
       rm -f /tmp/supabase.deb; \
       supabase --version
   ```
   This matches the official Supabase CLI release asset naming (`supabase_<ver>_linux_amd64.deb` / `arm64`), `dpkg --print-architecture` yields exactly `amd64`/`arm64`, `curl` + `ca-certificates` are installed in the *preceding* RUN block (correct ordering), and `supabase --version` acts as a build-time self-check so a failed install breaks the build rather than the runtime. This directly resolves the reported error.
2. **Build-arg plumbing** — `NEXT_PUBLIC_SEGMENT_WRITE_KEY` was already passed as a compose build arg but never declared/exported in the Dockerfile; it is now `ARG` + `ENV`'d, matching every other `NEXT_PUBLIC_*` var. This is a genuine latent bug fix (otherwise the value is silently dropped at bundle time).
3. **`package.json`** — `supabase db push --db-url "${SUPABASE_DB_URL}"` now quotes the connection string, which is required when the URL contains special characters (`&`, `?`, `#`, `$`). Correct shell-scripting hygiene.
4. **`docker-compose.ui.yml`** — dropped the stray `--debug` flag that was being forwarded into the npm script invocation. Correct: `npm run <script> --debug` is not a valid Supabase flag and, depending on npm version, is either swallowed or mis-forwarded.
5. `apt-get clean && rm -rf /var/lib/apt/lists/*` was added to keep the image lean — harmless and good practice. (Minor note: this makes a later `apt-get install -f` unable to fetch index data, but the Supabase `.deb` is effectively dependency-free, so the `||` fallback is a safety net rather than a required path.)
