1. Scope, protocol and evidence standards

Scope correction. All 29 multi-agent/related papers remain in scope, including attribution-only work. Section 7 now screens the full 20-paper harness set without privileging HarnessFix. The 29 entries are research papers on attribution, diagnosis, mitigation or closely related operations; they are not all claims of demonstrated repair.
Revision in response to the review correction. The unit of analysis is now an individual paper. Causal/counterfactual work is expanded; previously merged papers are separated. The report asks what each paper does, what HarnessFix and named harness papers already implement, and what precise adaptation remains unverified. The earlier preferred consumed-handoff recommendation is superseded.

Question. How do individual papers attribute failures, identify responsible steps/components/dependencies, and mitigate errors in multi-agent systems and agent harnesses? Which specific operations have a verified or partial counterpart across the two settings? Attribution quality is an independent endpoint; repair success is evaluated separately when the paper attempts repair.

Cutoff and sequence. Literature cutoff: 19 October 2026. Search and extraction proceeded multi-agent first, harness second, and cross-area citation/nearest-neighbor checks last. Retrieval timestamps and repository commits are retained in the audit. Preprints are eligible; no peer-review status is inferred from repository presence.

Search families. Combine LLM/agent/multi-agent/harness with error correction, failure recovery, debugging, attribution, intervention, communication repair, propagation, replanning, rollback/checkpoint/replay, memory correction, self-improvement, harness optimization/evolution and regression prevention. Exact executed queries and retrieved references are in the search register. Two search engines were used; primary arXiv/venue papers, appendices, author repositories, HF metadata and actual released files supplied evidence. Secondary results were leads only.

Eligibility. Core: a system changes an agent execution or persistent harness to address failure, with a describable intervention and outcome evaluation. Adjacent: diagnosis/detection, robustness injection, prevention, memory consistency, workflow/prompt optimization or evaluation work that supplies a mechanism, dataset or serious comparator. Exclude generic agent performance papers without a relevant mechanism, unsupported blogs and name-only matches from technical conclusions. A paper being adjacent does not make it unimportant.

Citation chasing. Backward chains included DoVer→Who&When/Reflexion/CRITIC; ARIA→DoVer/Spark/CausalFlow; Sherlock→AFlow and verifier families; HarnessFix→GEPA/SCOPE/ReCreate/Meta-Harness; RRSI→Meta-Harness/AHE/TTHE/HarnessX; memory rollback→MemoRepair. Forward-oriented exact-title searches found newer repair/evolution papers and official releases. This is web-index citation chasing, not a complete citation-database export.

Extraction. Separate timing, information privilege, attributed object, action, affected state, verification, learning, cost and label provenance. Treat proposed explanations, human annotations, injected origins and executed counterfactual effects as different evidence. Reported results are not replications. The audit did not run paid models, build every container, or reproduce paper scores.

Stopping. Stop after broad terminology passes, targeted backward/forward passes and release checks sufficient to identify serious baselines for three bounded pilots. This review did not reach global saturation: late checks still found AgentTether, dependency-guided memory rollback and RePAIR. It is a systematic, bounded evidence map, not an exhaustive review or a PRISMA census. Search-result counts are not publication counts. Remaining leads and unverified fields are explicit.

Inventory after revision: 30 multi-agent or explicitly adjacent paper entries; 21 individual harness entries; 15 supplementary paper-specific resource audits. Counts describe this bounded review, not field coverage.

9. Eight concrete directions, each anchored to a source paper

My provisional assessment: start with the AgenTracer-inspired attribution-label pilot if the immediate objective is standalone attribution. GCJR provides a sharper interaction-attribution question once RePAIR has been checked. ErrorProbe motivates a distinct diagnostic experiment-selection problem. Collator-style credit requires substantially more execution data. These are feasibility judgments, not claims that novelty or baseline headroom has been established.

All pilot sizes below are proposed starting points, not statistical power guarantees. Hold information access and total execution cost fixed. Do not train a new model until a small pilot reveals a reproducible failure of the relevant baselines.

Shared data design for attribution pilots

Change an actual harness component—code, prompt assembly, tool adapter, memory policy or control rule—and execute the task. Record the task, harness versions, component diff, environment snapshot, observable trace, intervention specification, whether it was enacted, downstream state and repeated outcomes. Keep injected origin, observed error location and successful repair location as separate fields. Keep no-op and resampling controls. Split by parent harness and fault family so variants of the same injected flaw do not appear on both sides of evaluation.

Successful component repair may be one attribution reference, but it does not establish a unique original cause. Multiple successful compensations and jointly necessary repairs require multiple or set-valued labels. Natural failures should eventually test whether conclusions survive beyond injected templates.

10. Evaluation depends on the chosen paper-level question

The questions in section 9 are hypotheses derived from sections 7–8. Select a concrete attribution target before choosing a model, and inspect the nearest harness comparator before treating a blank matrix cell as an opportunity.

First choose whether the question concerns attribution, intervention effects, repair, or a combination. Do not require a diagnostic method to demonstrate repair when attribution is the stated contribution.

  1. For attribution: specify the attributed object—agent, step, harness component, dependency edge, or set of interacting locations. Select valid reference labels or a controlled intervention-based target. Report the relevant localization, ranking, set-recovery or graph metric, diagnostic cost, and robustness. Injected origins, human responsibility labels and success-restoring interventions are different reference targets.
  2. For repair: specify the editable object, permitted information, continuation/restoration semantics and acceptance rule. Report recovery, regressions, repeated-run uncertainty and total execution cost separately from attribution accuracy.
  3. Select comparisons from all harness papers: use the actual matching operations in section 7. A partial match is a useful baseline with a stated limitation; an inaccessible full method is an unresolved check, not an established novelty gap.
  4. Keep causal claims bounded: a successful repair identifies an effective tested intervention, but need not identify a unique original cause. A model-imagined correction supports a different claim from an executed branch.
